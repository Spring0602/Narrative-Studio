# 用户数据守护（user-data-guard）

> **一句话**：项目更新（换版本、重建表、换库名）经常会**把用户数据清空**——账号、成员关系、模拟测试记录、反馈全没了。这个工具提前把用户数据存进“保险箱”，每次更新后自动检测；一旦发现被清空，**立刻把用户数据搬回来**，故事内容一个字都不动。

发给你的是一个**完整独立的小工具**，不依赖项目代码，放在任意文件夹都能用。

---

## 0. 前提条件

- **Python 3.10+**（安装时记得勾选 *Add python.exe to PATH*）
- **本机有 MySQL**，并且你知道连它的账号密码
- **不需要安装任何第三方包**（只用 Python 标准库 + 本机 `mysql.exe` / `mysqldump.exe`）

---

## 1. 为什么需要它（我们真遇到过的问题）

换一版代码 / 重新执行建表脚本 / 把演示数据整库覆盖过去，结果**用户数据被清空**，登录时才发现在。

- 前端更新本身不会删数据，**真正会删数据的是“后端的数据库脚本 / 建表初始化 / 整库覆盖”**，所以这个工具盯的是**数据库**。
- 它只关心「用户数据 + 用户相关记录」，**剧情节点、选项、世界观、角色这些“作品内容”一律不碰**。

### 它管的 6 张表（默认）

| 表 | 是什么 |
|---|---|
| `sys_user` | 用户账号本体（含密码哈希） |
| `project_member` | 用户与项目的关系（谁是拥有者/测试员） |
| `playtest_session` | 用户跑的模拟测试会话 |
| `playtest_step` | 每一次模拟测试的步骤明细 |
| `test_feedback` | 用户提交的测试反馈 |
| `player_progress` | 用户的跨局进度 |

### 可选（默认不搬，加 `--include-optional` 才带上）

| 表 | 为什么不默认搬 |
|---|---|
| `project_save` | 用户创建的存档，里面**含项目内容快照**，搬它等于动了作品内容 |
| `account_action_token` | 找回密码的临时令牌，一般没价值 |

## 2. 怎么用（三步，都靠双击）

> 下面提到的文件名就是**本文件夹里的文件**，双击运行即可。所有 `.bat` 会自动找到你机器上的 Python。

### 第 1 步：填配置 —— 双击 `1-填配置.bat`

按提示回答 5 个问题（MySQL 地址、端口、用户名、密码、要保护的数据库名），**看不懂的直接回车用默认值**。
重点是 **MySQL 密码** 和 **要保护的数据库名**这两项。

填完会生成 `guard.config.json`。也可以直接手动编辑这个文件。

### 第 2 步：建立保险箱 —— 双击 `2-建立保险箱.bat`

把当前的用户数据存进“保险箱”：输出会把 6 张表的**行数和内容指纹**列出来。
> 以后用户数据有较大变化时，再双击一次刷新即可。

### 第 3 步：开始监控 —— 双击 `3-开始监控.bat`

窗口开着就会守着，**一发现用户数据被清空，一两秒内自动搬回**：

```
[00:33:03] 🔴 检测到用户数据丢失（narrative_studio）！立即自动搬运……
[00:33:04] 搬运前备份：vault\backups\narrative_studio_搬运前_20261011_003303.sql
[00:33:05] ✅ 已自动把用户数据搬回 narrative_studio
```

不想守了，直接关窗口（或 `Ctrl+C`）。

## 3. 命令行用法（喜欢敲命令的看这里）

在本文件夹打开终端：

```bash
python guard.py init                  # 建/刷新保险箱
python guard.py check                 # 检测一次：用户数据有没有被动
python guard.py restore               # 把保险箱的用户数据搬回目标库
python guard.py watch                 # 常驻监控，发现被清空就自动搬运
python guard.py status                # 看当前状态摘要
```

常用选项：

```bash
python guard.py watch --interval 5                    # 每 5 秒检查一次
python guard.py watch --dry-run                       # 只报警、不自动搬（先观察用）
python guard.py check --db 某个库名                    # 只盯某一个库
python guard.py restore --to-db 新库名                 # 搬到另一个库
python guard.py restore --from-db 老库 --to-db 新库     # 不走保险箱，直接从老库实时搬
python guard.py check --include-optional              # 把存档表也一起保护
```

`watch` 默认会**自动发现**所有含 `sys_user` 表的库（新版本换了新库名也能盯上）。

---

## 4. 它怎么判断“被清空”（判定规则）

把当前库和保险箱逐个表比：

| 情况 | 判定 |
|---|---|
| 数据库整个不见了 | 🔴 需要搬运 |
| 某张用户表在库里没了（被重建/改名） | 🔴 需要搬运 |
| `sys_user` 行数变少（**账号少一个都算**） | 🔴 需要搬运 |
| 其他表掉了 ≥50% 的行 | 🔴 需要搬运 |
| 只是少了几条（<50%） | 🟡 只提示 |
| 行数没少 | ✅ 正常 |

另外会顺手告诉你「**代码版本变了**」（对比 `git HEAD` 和未提交文件数），这样你能分清“这次到底是代码更新还是数据被清”。

---

## 5. 新版本改了表结构怎么办

已适配两种情况：

1. **新增了列** —— 搬运时只写两边都有的列，新列走它自己的默认值；如果是「新增了 NOT NULL 且没有默认值」的列，会自动填安全占位值（数字填 `0`、文本填 `''`、时间填 `NOW()`），并在日志里提示。
2. **新库名** —— `watch` 会自动发现新库；也可以显式指定：
   ```bash
   python guard.py restore --to-db narrative_studio_v2
   python guard.py restore --from-db 老库名 --to-db 新库名
   ```

## 6. 安全设计（为什么它不会帮倒忙）

- **写库前一律先备份**目标库（存到 `vault/backups/`），要撤销随时可以导回去
- 默认 `INSERT IGNORE`：**新版本里已经存在的数据不会被覆盖**，只补缺失的行；
  想把同 id 的行用保险箱覆盖，才加 `--mode=replace`
- 导入期间临时关闭外键检查（`SET FOREIGN_KEY_CHECKS=0`），避免因为剧情内容不同而整批失败
- 导入包在一个事务里；失败会把出错 SQL 存到 `logs/last_restore_error.sql`
- 所有动作都写日志：`logs/guard_YYYYMMDD.log`、`logs/restore_*.log`

## 7. 文件说明

```
用户数据守护-发给队友/
├─ 使用说明-先看这个.txt      30 秒上手（建议先看这个）
├─ 1-填配置.bat             双击 = 配置向导
├─ 2-建立保险箱.bat          双击 = 建/刷新保险箱
├─ 3-开始监控.bat            双击 = 常驻监控 + 自动搬运
├─ setup-config.py          配置向导脚本（被 1-填配置.bat 调用）
├─ guard.py                 主程序（只用 Python 标准库）
├─ guard.config.json        配置：数据库连接、目标库、要保护的表
├─ vault/                   保险箱（第一次运行后自动生成）
│  ├─ vault.json            元数据：行数 + 内容指纹 + 代码版本
│  ├─ user_data.json        数据本体（含密码哈希，自己留着别外发）
│  ├─ user_data.sql         同上的 SQL 版，方便人工恢复
│  └─ backups/              每次搬运前对目标库的完整备份
└─ logs/                    运行日志
```

**注意**：`vault/` 里存着用户数据快照（含密码哈希），自己留着就行；`guard.config.json` 里有你的数据库密码，也不要外发。

## 8. 本地实测记录（2026-10-11，在临时沙箱库验证过）

为了不动真实数据，测试在一个临时库（真实库的完整副本）上做，测完已删除：

| 步骤 | 结果 |
|---|---|
| 建保险箱 | 6 张表 / 219 行，指纹全部记录 |
| 模拟“更新清空用户数据”（清空 5 张用户表 + 给 `sys_user` 加 2 个新列） | — |
| `check` | 🔴 WIPED，逐表列出“少了几行”，并提示结构新增了 `nickname` / `login_count` |
| `restore` | 5 张表全部复原：23 / 27 / 35 / 121 / 13；新增的必填列自动补 `''` 和 `0` |
| 内容复核 | 与真实库**逐行指纹完全一致**（含密码哈希） |
| `watch` 自动模式 | 数据被清空后 **1 秒内自动搬回**，无需人工干预 |
| 真实库影响 | **零改动**（测前测后都是 23 用户 / 35 会话） |
