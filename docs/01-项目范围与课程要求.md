# 项目范围与课程要求

## 1. 产品定位

叙事工坊将互动剧情表示为“项目—设定—角色—节点—选择—条件—状态变化—测试路径”的结构化系统。创作者可以编辑，测试者可以运行，系统可以检测结构问题。AI 是增强能力，不是核心闭环的依赖。

## 2. 课程要求对照

| 课程硬性要求 | 框架落实方式 | 后续成果证据 |
|---|---|---|
| Java 核心业务逻辑 | 权限、规则计算、状态变化、图检测放在 Service | Service 代码、单元测试、序列图 |
| MVC / 多层架构 | Vue 表示层 + Spring Controller/Service/Mapper | 架构图、包结构、类图 |
| Hibernate 或 MyBatis | 使用 MyBatis-Plus，保留 Mapper 层 | Mapper、SQL、表结构 |
| 数据库后端 | MySQL 8，通过 SQL 脚本建库并使用 Navicat 管理 | E-R 图、schema.sql、Navicat 执行记录 |
| 主流前端框架 | Vue 3 + TypeScript + Element Plus | 页面、路由、组件 |
| 需求与详细设计 | 按角色、用例、业务实体、模块、UI、数据库撰写 | 阶段二 PDF |
| 测试 | 后端单元/集成测试、前端类型检查、业务验收脚本 | 测试报告与运行截图 |
| 可部署源代码 | README、环境样例、可由 Navicat 执行的 MySQL SQL 脚本 | 小于 20 MB 的源码 ZIP |
| 大模型使用说明 | 单列使用场景、输入输出、人工复核和风险 | 总报告第 6 章 |

## 3. 课程版优先级

### P0：必须形成闭环

- 账户注册、登录与 JWT 鉴权
- 项目与成员权限
- 世界观和角色档案
- 节点、选择和可视化连接
- 状态变量、条件与效果
- 从起点开始模拟、记录路径和状态快照
- 检测孤立节点、不可达节点、意外死路和循环

### P1：时间允许应完成

- 测试反馈与问题处理状态
- 角色知识边界的结构化录入
- 剧情 JSON 导入导出
- 结局覆盖统计
- AI 候选对话或一致性审查（二选一）

2026-09-12 状态：上述P0/P1后端已实现，AI选择“候选对话”，默认关闭。剧情交换仅含图/变量/规则，不是全项目备份。新增P1前端入口和真实MySQL、SMTP、模型与浏览器验收仍待完成，见 [本轮收口记录](13-后端收口与整体检查记录.md)。

### P2：课程后产品化

- 实时协作、版本分支与冲突合并
- Godot/Unity 插件
- 复杂表达式语言
- 基于角色信念和价值排序的动态剧情推演
- 商业化团队空间、模板市场和用量计费

## 4. 明确不做

- 不开发完整游戏引擎、地图、战斗和动画系统。
- 不从零训练大模型。
- 不允许 AI 功能失败导致剧情编辑和模拟不可用。
- 第一版不做任意脚本执行，规则采用白名单操作符。
- 第一版不追求 Google Docs 级实时多人编辑。

## 5. 角色和权限基线

| 角色 | 读项目 | 改设定/剧情 | 运行测试 | 管成员/归档 |
|---|---:|---:|---:|---:|
| OWNER | 是 | 是 | 是 | 是 |
| EDITOR | 是 | 是 | 是 | 否 |
| TESTER | 是 | 否 | 是 | 否 |
| 系统管理员 | 依管理用例 | 否 | 否 | 处理系统级数据 |

所有项目子资源 API 必须包含 `projectId`，Service 必须先验证成员身份，再访问子资源；不得只凭节点 ID、角色 ID 直接修改。
