# 数据库接口补全与联调说明

更新日期：2026-09-10。适用于当前 Java 后端与 20 表扩展数据库。

## 1. 实现范围和部署前提

本次补齐角色关系、角色知识、节点出场角色、选项草稿、结构检测与问题处理、测试反馈、发布版本、知识快照、邮箱验证和密码找回的后端接口；另补系统管理员用户列表与禁用/启用接口。前端页面不在本次实现范围。

**新后端必须连接已完成扩展的 20 表数据库。** 原 17 张基础表的 SQL 保留；新增 3 张表，扩展 4 张已有表，字段与 database/database-design/schema-extension.sql 一致。

- 应用启动执行只读列存在性检查；不会自动建表、执行扩展或修改已有数据。
- 已有 20 表测试库：先核对数据库名称和扩展字段，不可重复执行扩展脚本。
- 只有 17 表：备份后先在独立测试库按数据库目录 README 验证升级，再决定业务库升级。
- JSON 字段内容由后端生成，不能接受客户端直接上传发布快照或修改试玩快照。
- 本次开发没有连接核验或升级真实 MySQL；H2 测试不等于 MySQL 原生 JSON/外键/锁与 SMTP 实测。

所有项目写接口拒绝归档项目；读写均校验项目权限与资源归属。TESTER 不具有编辑、发布或处理状态权限。项目 OWNER 与系统 ADMIN 是两个不同概念；注册不会授予 ADMIN。

## 3. 请求与响应字段

### 3.1 关系、知识、出场角色

关系创建/修改：

```json
{"sourceCharacterId":11,"targetCharacterId":12,"relationType":"TRUST","description":"信任关系"}
```

sourceCharacterId、targetCharacterId 必须属于同一项目且为 ACTIVE 角色；禁止自身关系。relationType 必填、最长 40 字符，数据库保证有向角色对与类型唯一。description 可空、最长 1000 字符。返回 id/projectId 及请求字段；修改允许用 null 清空说明。

知识创建/修改：

```json
{"knowledgeKey":"secret","knowledgeLevel":"KNOWN","description":"发现秘密","acquiredNodeId":102}
```

knowledgeKey 匹配 [A-Za-z][A-Za-z0-9_]{0,99}，同一角色唯一；knowledgeLevel 为 UNKNOWN/SUSPECTED/KNOWN。acquiredNodeId 可空，非空时必须属于同一项目；修改传 null 可清除获得节点及说明。返回 id/projectId/characterId 及请求字段。

出场角色整体替换：

```json
{"characterIds":[11,12]}
```

最多 200 个，不允许重复；全部校验成功后才清除旧关联并写入新关联，失败整批回滚。空数组清空关联，返回排序后的 ID 数组。出场关联不自动授予角色知识。

### 3.2 草稿

```json
{"sourceNodeId":101,"choiceText":null,"sortOrder":0}
```

sourceNodeId 必须是本项目非结局节点；choiceText 允许空、最长 500 字符；sortOrder 必填且非负。返回 id/projectId/sourceNodeId/choiceText?/sortOrder/createdBy/createdAt/updatedAt。

转正请求：

```json
{"targetNodeId":103}
```

转正前须有非空选项文本，目标节点须在同一项目。正式选项创建成功后删除草稿，同一事务内完成；失败保留草稿。成功返回原有 ChoiceSummary，草稿不能重复转正。草稿不会进入运行图、结构检测或发布快照。

### 3.3 检测问题和反馈

检测返回本次仍存在的问题数组。问题字段：id/projectId/issueType/severity/targetType/targetId?/message/status/detectedAt/resolvedAt?。

检测规则：START_COUNT、ISOLATED、UNREACHABLE、DEAD_END、CYCLE、BROKEN_REFERENCE、ENDING_OUTGOING。忽略停用选项；不求解条件可满足性。最多 500 个节点，基于 BFS 可达性与每节点循环可达性判定；循环属于 WARNING，不自动禁止发布。

重复检测按类型、目标类型、目标 ID 复用记录；仍存在的 RESOLVED 问题重新 OPEN；IGNORED 保持忽略；消失的 OPEN 问题自动 RESOLVED。现有数据库没有检测批次表，因此不返回或伪造 runId，也不保存完整批次历史。

反馈创建：

```json
{"sessionId":42,"stepId":1010,"title":"分支说明不清晰","description":"到达该步后发现问题"}
```

sessionId、stepId 均可不传；指定 stepId 必须同时指定 sessionId。只能关联本人在当前项目的会话；步骤必须属于该会话。title 必填、最长 150 字符；description 必填、最长 10000 字符。返回 id/projectId/sessionId?/stepId?/reporterId/title/description/status/createdAt/updatedAt。

问题及反馈状态请求统一：

```json
{"status":"RESOLVED"}
```

状态只允许 OPEN/RESOLVED/IGNORED。反馈不提供删除接口，保留追溯记录。项目编辑者能读反馈关联的会话/步骤 ID，但原有试玩读取接口仍仅允许会话本人访问，不因反馈开放他人完整试玩历史。

### 3.4 发布版本和试玩

发布与版本试玩均无请求体。发布返回 id/projectId/versionNo/publishedBy/publishedAt/schemaVersion；版本号按项目递增，项目行锁保证并发分配不重复。发布要求 1 至 500 个节点、唯一起点、合法连接及类型正确的规则。

schemaVersion=1 的内容包括项目资料、节点、正式选项、变量、条件、效果、世界观、ACTIVE 角色、角色关系、知识定义和出场关联。不含账号密码、凭据、草稿或其他用户的试玩历史。版本不提供更新/删除接口。

- 原 POST P/playtests 保留“当前编辑版”模式。
- POST P/releases/{releaseId}/playtests 使用固定版本的节点正文、选择、规则、变量和知识定义。
- 现有执行选择、回放、终止接口同时适用于两种模式。
- 发布版会话 restart 继续使用同一 releaseId；当前编辑版 restart 使用最新定义。
- 会话响应新增 releaseId?、knowledge；步骤响应新增 knowledgeBefore/knowledgeAfter。
- 已发布节点和选项禁止物理删除，保留现有试玩外键需要的 ID；仍可编辑或停用当前版本，历史快照不变。
- 当前编辑版会话仍可能受后续规则编辑影响；不能将其描述为冻结版本。

知识快照示例：

```json
{"11:secret":"KNOWN","12:clue":"SUSPECTED"}
```

键为 characterId:knowledgeKey。acquiredNodeId 为空表示初始知识；到达指定节点时首次获得该定义的等级；循环再次进入不覆盖已获得值。它是按节点获得知识的最小实现，不是独立的知识条件/效果脚本系统，不自动推理或降级。仅更新会话快照，不回写 character_knowledge。旧步骤的空知识快照读取为空对象。

frontend/src/api/playtests.ts 已补 releaseId 与知识字段类型，以及 startReleasedPlaytest 封装；页面由 B 继续接入。

### 3.5 账户与管理员

邮箱申请：{email,password}，password 为当前密码；确认：{token}。
密码重置申请：{email}；确认：{token,password}，password 为新密码。
登录后改密：{currentPassword,newPassword}。
管理员改状态：{status:"ACTIVE"} 或 {status:"DISABLED"}。

新密码 8 至 72 字符，且 UTF-8 编码不得超过 72 字节。邮件令牌为 32 字节安全随机数的 Base64URL 字符串（43 字符），15 分钟有效；数据库仅保存 SHA-256 摘要。确认使用用户行与凭据行锁，重复、过期、错误用途的令牌返回 400。

申请接口返回通用受理文案；找回密码只针对已验证邮箱。每账户 60 秒内最多生成一次凭据；同一实际来源 IP 对账户凭据接口每分钟最多 20 次，超限返回 429 RATE_LIMITED。单实例限流不信任客户端 X-Forwarded-For；集群或反向代理部署需在可信网关配置分布式限流。

确认邮箱、修改/重置密码、管理员改状态会递增 token_version 并撤销未使用的账户凭据。JWT 每次访问对照数据库中的版本与 ACTIVE 状态；旧 Token 失效，客户端须重新登录。旧 JWT 缺少版本字段时按 0 处理。API 不提供列出令牌或读取摘要的接口。

SMTP 未配置返回 503 MAIL_UNAVAILABLE。密码重置投递失败会回滚凭据事务并记录不含地址、令牌的告警，对外仍保持通用受理响应，避免泄露账户存在性。受理响应不是投递成功保证。

## 4. SMTP 与数据库配置

默认不开启邮件发送。测试用替身捕获邮件，不向真实邮箱发送。需要真实邮件时设置环境变量：

- SPRING_PROFILES_ACTIVE=mail
- SMTP_HOST、SMTP_PORT（默认 587）、SMTP_USERNAME、SMTP_PASSWORD、SMTP_FROM

application-mail.yml 默认要求 STARTTLS，连接、读、写超时均为 5 秒；使用服务商支持的端口与授权密码。不要将凭据提交到 Git。当前邮件包含待手动提交的令牌，尚未制作前端确认页或自动跳转链接。

配置采用 Spring Boot 的邮件适配方式，参考 [官方邮件配置说明](https://docs.spring.io/spring-boot/3.5/reference/io/email.html)。

DB_URL 应明确指定已验证的库，例如 narrative_studio_design_test；账号需具有业务 DML 权限。Spring Boot 不会自动加载仓库 .env，须由启动环境/IDE 注入。开发过程不自动替换用户连接配置。
