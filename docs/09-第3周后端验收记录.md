```powershell
mvn -f backend/pom.xml clean package
```

常规测试共执行102个案例，全部通过；另有1个真实 MySQL 测试默认跳过：

| 测试组 | 案例数 | 内容 |
|---|---:|---|

集成测试使用独立 H2 内存库，不连接业务库。测试 DDL 是 schema.sql 的测试镜像：移除 MySQL 专用建库/引擎语法，快照 JSON 列在 H2 中用 CLOB 存储。因此 H2 测试不等于 MySQL 原生 JSON、排序规则与所有锁行为验证。

前端 `npm run typecheck` 与 `npm run build` 均已通过。验证过程中为现有 tsconfig.node.json 补齐 noEmit，修复 TS5096 构建错误，并忽略 TypeScript 增量缓存；未开发 B 负责的页面。Vite 仍提示现有主包大于500 kB，该提示不阻断构建。

关键通过场景：

- trust 初始为 `"30"`，执行 ADD `"20"` 后为 `"50"`，隐藏分支可用，到达 ENDING 后自动完成。
- 两个线程以相同 expectedStepNo 提交同一自环选择，仅一次成功，仅新增一步。
- 步骤和会话更新后发生后续规则错误，整个事务回滚，节点与快照均恢复。
- 重新开始时起点配置非法，旧会话的终止操作一并回滚。
- 非成员、其他项目资源、同项目其他人的会话、TESTER 编辑、归档写入均被拒绝。
- 非法规则替换保留旧规则，引用变量不可删除或换类型；描述可清空。
- HTTP 400/401/403/404/409 与成功响应格式通过检查。

## 4. B 的前端联调顺序

1. 使用 OWNER/EDITOR 创建 INTEGER 变量 trust，initialValue 传 `"30"`；可另外创建 BOOLEAN、STRING 变量验证表单。
2. 在画布创建起点 S、中间节点 M、结局 E，连接 S→M 和 M→E。
3. 为 S→M 保存 ADD `"20"` 效果；为 M→E 保存 GTE `"50"` 条件。变量 ID 使用创建接口的返回值。
4. TESTER 创建会话，展示当前节点、state、availableChoices；所有状态值按字符串接收，根据变量类型呈现。
5. 执行选择时提交当前 stepNo，成功后整体更新会话响应；请求期间禁用重复点击。409时重新获取会话，不自动重发旧选择。
6. 步骤面板显示第0步和每次 stateBefore/stateAfter；到达结局后显示完成状态。
7. 重开后替换当前 sessionId；旧会话历史仍可查询。编辑变量前先终止所有 RUNNING 会话。

本周采用“当前规则 + 历史状态快照”，不保存完整剧情内容版本；编辑规则后会影响未来的选项计算，已经保存的状态不会重算。
