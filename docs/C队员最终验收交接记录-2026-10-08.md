### 2. npm 依赖漏洞处理（已完成，含残留风险说明）

- 处理前：8个漏洞（2个moderate、6个high）。
- 执行 `npm audit fix` 修复传递依赖，剩6个。
- 升级主版本内部的最新版：`vue` 3.5.12→3.5.43、`axios` 1.7.7→1.20.0、`element-plus` 2.8.6→2.14.7、`vite` 5.4.10→5.4.21。
- 处理后：**3个漏洞（2个moderate、1个high）**。
- 残留风险说明：剩余3个漏洞均来自 `vite → esbuild` 开发服务器链路（`@vitejs/plugin-vue` 依赖旧版 `vite`），影响面仅限本地开发服务器，不影响生产构建产物。官方修复需将 `vite` 破坏性升级到 8.x，会与当前 `@vitejs/plugin-vue` 5.2.0 不兼容，故本轮不升级，作为已知风险记录，待后续统一升级依赖链时处理。
- 升级后回归验证：`npm test` 20项通过、`npm run typecheck` 通过、`npm run build` 通过。

### 3. 排查中定位的问题（本地已验证修复，代码改动未纳入本次提交）

| 问题 | 现象 | 修复 |
| --- | --- | --- |
| CORS 白名单过窄 | 浏览器从 `http://127.0.0.1:5173` 访问时，登录请求带 `Origin: http://127.0.0.1:5173`，后端白名单仅含 `http://localhost:5173`，请求被直接拒绝（403）。curl 不带 Origin 头，因此命令行测试一直显示200，问题只在真实浏览器出现。 | `SecurityConfig.java` 的 CORS 来源改为支持逗号分隔多来源；`application.yml` 默认值改为 `http://localhost:5173,http://127.0.0.1:5173` |
| Vite 代理目标解析 | Windows 上 `localhost` 可能优先解析为 IPv6 `::1`，导致代理连不上后端。 | `vite.config.ts` 代理 target 由 `http://localhost:8080` 改为 `http://127.0.0.1:8080` |

### 4. 本地验收账号面板的凭据处理（涉及代码，未纳入本次提交）

登录页的「本地验收账号」面板（仅开发模式显示）原先把测试账号与密码明文写在 `LoginView.vue` 中。由于本仓库为**公开仓库**，明文密码会被公开，因此本地已改为：

- 账号信息从 Vite 环境变量读取（`VITE_DEV_ANNIE_USER` 等），代码中不再出现任何明文密码。
- 真实凭据存放于本地 `frontend/.env.local`（已加入 `.gitignore`，不提交仓库）。
- 提供模板文件 `frontend/.env.local.example` 供团队成员复制使用。
- 未配置环境变量时面板不显示；正式构建（`import.meta.env.DEV` 为 false）同样不显示。
