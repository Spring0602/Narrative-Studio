# 课程交付物清单

## 阶段二：需求分析与详细设计书

- 系统角色及其功能
- 总体功能需求和每个用例规定
- 主事件流、备选事件流、前置/后置条件
- 业务实体分析
- 性能、安全和外部接口等非功能需求
- 基于 MVC 的软件架构
- 功能模块划分
- 关键功能的 MVC 资源清单、UML 序列图和类设计
- 页面原型与跳转关系
- E-R 图、逻辑结构与物理表结构
- 输出 PDF

## 编码阶段

- 与需求一致、可运行的前后端源码
- `database/schema.sql` 和必要演示数据
- 依赖与部署说明
- 单元测试、集成测试和功能测试记录
- 源码 ZIP/RAR 小于 20 MB

## 总报告

1. 引言：背景、现状、目的、应用。
2. 需求分析：业务流程、相关模型、功能与非功能需求。
3. 项目设计：架构、模块、数据库、主要算法。
4. 项目开发：技术方案、关键模块、数据结构、少量关键代码、问题与解决。
5. 个人体会：每人各写一份分工、贡献、问题、收获与建议。
6. 大模型使用说明：使用了什么模型、在哪些环节使用、如何复核；区分“开发辅助使用”和“产品内 AI 功能”。

另需记录：团队分工、总代码量、每人贡献和个人代码量。代码量只能作为辅助证据，应结合 PR、功能负责人、测试与文档贡献说明。

### 三人贡献材料分配

| 成员 | 主要贡献 | 必留证据 |
|---|---|---|
| 开发者 A | Java 后端、接口、权限、事务、规则与图算法 | 后端提交、单元/集成测试、接口与技术说明 |
| 开发者 B | 前端、可视化、API联调与数据库审查 | 前端提交、构建/交互记录、数据库评审意见、关键迁移复验记录 |
| 成员 C | 数据库开发、SQL/演示数据、各类测试统筹、文档整合与答辩 | 数据库/迁移/测试脚本提交、E-R维护、Navicat记录、测试报告、缺陷复测、答辩与演练记录 |

本次调整后，C以数据库和测试脚本作为主要技术交付，继续负责答辩；A/B提供各自技术章节、截图与测试素材，由C整合，避免C独自承担全部材料。新分工不改写历史贡献；已完成SQL与测试仍按原提交作者归属，B的审查贡献和C的后续开发分别留证。最终分工须与Git、测试和文档记录一致。
