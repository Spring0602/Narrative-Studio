# 课程交付物清单

## 阶段二：需求分析与详细设计书

- 系统角色及其功能
- 总体功能需求和每个用例规定
- 主事件流、备选事件流、前置/后置条件
- 业务实体分析
- 性能、安全和外部接口等非功能需求
- 基于 MVC 的软件架构
- 功能模块划分
- 关键功能的 MVC 资源清单、UML 序列图和类设计
- 页面原型与跳转关系
- E-R 图、逻辑结构与物理表结构
- 输出 PDF

## 编码阶段

- 与需求一致、可运行的前后端源码
- `database/schema.sql` 和必要演示数据
- 依赖与部署说明
- 单元测试、集成测试和功能测试记录
- 源码 ZIP/RAR 小于 20 MB

## 总报告

1. 引言：背景、现状、目的、应用。
2. 需求分析：业务流程、相关模型、功能与非功能需求。
3. 项目设计：架构、模块、数据库、主要算法。
4. 项目开发：技术方案、关键模块、数据结构、少量关键代码、问题与解决。
5. 个人体会：每人各写一份分工、贡献、问题、收获与建议。
6. 大模型使用说明：使用了什么模型、在哪些环节使用、如何复核；区分“开发辅助使用”和“产品内 AI 功能”。

另需记录：团队分工、总代码量、每人贡献和个人代码量。代码量只能作为辅助证据，应结合 PR、功能负责人、测试与文档贡献说明。

### 三人贡献材料分配

| 成员 | 主要贡献 | 必留证据 |
|---|---|---|
| 开发者 A | Java 后端、接口、权限、事务、规则与图算法 | 后端提交、单元/集成测试、接口与技术说明 |
| 开发者 B | 前端、数据库、SQL、Navicat 验证、可视化与联调 | 前端与数据库提交、E-R 图、SQL 文件、Navicat 执行截图、构建记录 |
| 成员 C | 少量开发、测试验收、文档统筹、演示与答辩 | 演示数据或验收脚本提交、缺陷记录与复测结果、报告修订记录、答辩稿和演练记录 |

成员 C 虽然开发量较少，仍应至少承担一项可独立验收的代码或自动化测试任务，并保留本人提交记录；文档和答辩贡献需用版本记录、材料清单和演练记录体现。最终报告中的个人分工应与 Git、测试和文档证据一致。

## 建议留存的过程证据

- 每周可运行版本的 Git Tag
- 需求/接口评审记录
- 关键页面截图与演示视频
- 测试命令输出或 CI 记录
- 典型缺陷及修复前后结果
- 大模型提示词、采纳/未采纳内容与人工修改说明

## 最终命名提醒

- 报告：`组号+设计总报告.pdf`
- 程序：`组号+系统名称.zip`
- 在线提交时间和组号以课程 QQ 群最终通知为准。
