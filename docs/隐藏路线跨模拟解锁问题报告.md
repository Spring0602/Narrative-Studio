# 隐藏路线解锁状态无法在模拟测试中继承的问题

## 问题概述

当前项目将“隐藏路线已解锁”（`hidden_routes_unlocked`）定义为初始值为 `false` 的状态变量，并以它作为罗吉线、希尔法法线等隐藏路线选项的出现条件。

当设计规则是“完成四条主线后，解锁两条隐藏路线”时，模拟测试无法复现解锁后的路线：每次重新开始模拟都会回到初始状态，`hidden_routes_unlocked` 又恢复为 `false`。因此，即使此前已经完成四条主线并达成解锁条件，隐藏路线选项仍不会在新的模拟中出现。

## 复现步骤

1. 在“状态变量”页面确认 `hidden_routes_unlocked` 的初始值为 `false`。
2. 在剧情节点中查看隐藏路线选项，例如“跟随希尔法法进入雾海”。
3. 该选项配置的出现条件为：`hidden_routes_unlocked = true`。
4. 从模拟测试开始，完成四条主线并使解锁逻辑生效。
5. 再次点击“重新开始模拟”，或新开一次模拟测试。
6. 回到起始节点查看可选项。

## 实际结果

重新开始后，模拟状态按初始值重置，`hidden_routes_unlocked` 重新变为 `false`；罗吉线、希尔法法线等依赖该变量的隐藏路线不会显示。

## 预期结果

如果产品规则定义为“玩家累计打通四条主线即可永久解锁两条隐藏路线”，则解锁状态应独立于单次模拟会话保存。重新开始模拟后，隐藏路线仍应保持已解锁并可选择。

## 影响范围

- 无法在模拟测试中验证“多周目／累计通关解锁”玩法。
- 隐藏路线的实际可达性无法完整验收。
- 测试人员可能误判路线条件或剧情配置存在问题。
- 当前状态变量机制更适合单次流程内的临时状态，不适合跨模拟会话的永久进度。

## 建议方案

建议区分两类状态：

1. **会话状态**：随“重新开始模拟”恢复初始值，例如好感度、线索数、当次路线进度。
2. **持久进度**：不随重新开始模拟清空，例如已通关主线集合、已解锁隐藏路线。

可考虑新增“玩家进度／存档”数据，保存已完成主线数量或已解锁路线标识；模拟启动时读取该进度。并提供测试辅助能力，例如重置进度、手动设置已通关路线，方便验证隐藏路线。

## 当前结论

这不是单个剧情节点条件配置错误，而是“跨模拟会话的解锁进度”缺少持久化承载位置。若产品只要求单次流程内解锁，则当前重置行为符合预期；若要求完成多条路线后永久解锁隐藏路线，则需要补充持久进度设计与实现。
