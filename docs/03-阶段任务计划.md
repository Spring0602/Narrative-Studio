# 阶段任务计划（三人团队）

更新日期：2026-09-10。以当前本地源码、SQL和已有测试记录为基线。本次职责调整不追溯改写历史贡献；五周路线作为交付框架，按实际缺口推进，不重复开发已完成后端。

## 1. 分工原则

| 成员 | 主责 | 配合与审查 | 责任边界 |
| --- | --- | --- | --- |
| A：后端主开发 | Java接口、权限、事务、规则、图算法、版本与账户安全；后端缺陷修复 | 复核SQL与实体/Mapper/DTO兼容性，配合数据库、性能和安全测试 | 继续维护后端单元/集成测试，C统筹测试不替代A的代码质量责任 |
| B：前端主开发、数据库审查 | 页面、交互、可视化、API接入、前端类型/构建及缺陷修复 | 审查C的E-R、表字段、索引/外键、迁移安全及页面数据需求 | 不再默认主写SQL、演示数据或负责Navicat执行；审查意见由C落地 |
| C：数据库主开发、测试统筹、答辩 | 接管已有数据库，维护SQL、迁移、演示数据、Navicat记录；组织各类测试、缺陷跟踪和复测 | 汇总文档、测试证据、演示与答辩；数据库由B审查、A复核后端兼容性 | 基于已有20表补齐交付，不重建数据库，也不独自承担前后端全部缺陷修复 |

- A、B仍为应用代码主开发；C从“少量开发与答辩”调整为“数据库、测试和答辩”，以SQL、测试脚本和验收证据为主要技术交付。
- 避免C过载：A/B各自提供模块说明、截图和测试结果，C负责整合；不再额外分配C主开发页面或复杂Java业务。
- 数据库变更流程：C提交方案/SQL → B审查设计与使用需求 → A确认映射与事务兼容 → C在独立测试库验证并记录；涉及已有数据先备份。
- 分别记录“代码已实现”“原型已完成”“真实环境验收通过”，不能把mock、建表文件或构建成功等同业务闭环。

## 4. 从现在开始的执行顺序

### 第一批：数据库接手与基础联调

- [ ] C接收 database/schema.sql、database/database-design/、database/system-design/ 和现状说明；记录实际库名、版本、表结构、已执行扩展，避免重复DDL。
- [ ] B审查字段、索引/唯一约束、外键删除、E-R与新增表/列的一致性，形成问题清单；不能假定现有图示已同步20表。
- [ ] A配合C确认DB_URL、权限、实体/DTO和启动检查，复现真实MySQL冒烟测试。
- [ ] B将成员原型接真实API，补项目详情/编辑/归档所需页面。
- [ ] C组织OWNER/EDITOR/TESTER及跨项目越权测试；A/B分别修后端/前端，C复测。

### 第二批：打通核心闭环

- [ ] B按世界观/角色 → 剧情画布与草稿 → 规则编辑 → 模拟与回放逐模块接入。
- [ ] C先准备可运行的小剧情，再扩充到10节点2结局，包含条件/效果、正常路径、异常样例及可重复准备步骤。
- [ ] A处理契约与事务缺陷；C编写/执行接口和数据库验收脚本；B审查数据是否支持页面展示。
- [ ] C在真实MySQL核验JSON、关联一致性、重复请求和发布后编辑不影响冻结试玩。

### 第三批：质量、扩展与答辩

- [ ] B接入检测定位、反馈处理、关系/知识、发布和账户页面，补加载/空态/错误/权限状态。
- [ ] C组织端到端、回归、性能、安全测试；SMTP条件具备后验证投递与凭据失效。
- [ ] A/B修复各自模块并补回归用例；C负责复测，不由C代修所有缺陷。
- [ ] A/B提交模块说明和截图，C整合数据库说明、测试报告、演示脚本和答辩稿。
- [ ] 三人确认课设最终范围，基础闭环优先于美化和非必要扩展；不因工期紧张静默删除必需模块。

## 6. 每周节奏与阶段门禁

- 周一：三人确认当前批次缺口、字段/API、负责人和验收标准。
- 周二至周四：A后端修复/联调；B前端开发并安排数据库审查；C数据库开发与逐模块测试。
- 周五：C组织真实环境联调和回归，A/B定位修复，问题按所属模块分派。
- 周末：C汇总进度、数据库/测试证据；A/B提交各自材料，共同校对答辩口径。

阶段完成须同时满足：

1. 主流程和至少两个异常流可复现，不只在mock中成功。
2. 权限、项目及子资源归属检查有效；刷新后数据一致。
3. 后端测试、前端类型/构建通过；真实MySQL、SMTP等分别标记通过、待测或阻塞。
4. 数据库变更具有C的SQL/执行记录、B审查结论、A兼容性确认；不提交密钥、真实用户数据或本地库目录。
5. 接口、SQL、前端类型、测试、说明和必要截图同步，至少一名非作者能新环境复现。
6. P0缺陷关闭；待验收项明确负责人和前置条件，不能改记“已完成”。
7. Git、个人贡献、审查与测试记录一致，不改写历史作者。

## 7. 答辩与材料

- C继续主讲和控时，主答数据库、SQL、Navicat、测试设计及质量证据。
- B主答前端交互、可视化、API接入和数据库审查取舍。
- A主答接口、权限、事务、规则/图算法、版本冻结与安全设计。
- A/B各自编写模块说明和提供素材，C整合总稿；三人熟悉完整闭环。

建议演示：OWNER登录与协作 → 角色/知识/变量 → 主线、隐藏分支和两个结局 → 孤立节点检测定位 → 发布试玩与状态/知识变化 → 结局及快照回放 → 提交处理反馈。AI仅按实际实现或开发辅助用途陈述，不演示未实现功能。
