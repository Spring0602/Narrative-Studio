## 4. 后端与数据库对接重点

### 4.1 本轮新增：project_save

执行文件：[history-extension.sql](../database/database-design/history-extension.sql)；只读核验：[verify-history.sql](../database/database-design/verify-history.sql)。

| 对象 | C需核对 | 对应后端行为 |
| --- | --- | --- |
| id、project_id、saved_by | BIGINT；id自增主键；项目和用户外键 | 保存所属项目、保存人及恢复权限 |
| save_kind、auto_slot | MANUAL/AUTO；手动slot为NULL，自动slot为保存人ID | 手动版本项目共享，自动草稿按用户隔离 |
| uk_project_auto_slot | UNIQUE(project_id,auto_slot)；允许手动记录的NULL | 每项目每用户最多1份自动草稿，不可误改为project_id单列唯一 |
| revision | BIGINT非空，默认1 | 多窗口乐观校验；冲突返回409，不静默覆盖 |
| label、content_hash | VARCHAR(100)、CHAR(64)，均非空 | 版本备注和内容去重摘要 |
| content_snapshot | JSON非空 | 整体创作快照与未提交表单，不改成不兼容的普通字段 |
| saved_at | DATETIME(6)，默认CURRENT_TIMESTAMP(6) | 无变化跳过时保持原保存时间 |
| idx_project_save_history | (project_id,save_kind,id) | 查询最近5次手动记录 |
| 外键删除行为 | 项目外键ON DELETE CASCADE；用户外键保持脚本定义 | 不自行新增用户级联删除或改变历史记录归属 |

“手动最多5份”由后端在项目锁和事务中清理；自动草稿去重和修订号也由后端处理。C无需另建定时器、触发器或事件任务。10分钟计时在前端，页面关闭后不会后台持续保存。

### 4.2 若旧扩展尚未落库

核对state_variable.persistence_scope、story_choice.unlock_rule、playtest_step.progress_before/progress_after及player_progress。已有且一致则不重跑，不修改原节点/选项ID、不清空现有模拟或发布记录。详细字段和四线解锁验收见C指南。

### 4.3 A与C共同完成的接口联调

结构核验通过后，将同一版本后端连接到独立测试库，保持启动结构检查开启。以下接口前缀均为 /api/projects/{projectId}/saves：

| 接口 | 数据库观察点 |
| --- | --- |
| GET；GET /{id} | 返回项目手动历史与本人自动草稿；预览不写数据 |
| POST | 新增MANUAL；连续6次后只剩最近5份 |
| PUT /auto | 有变化更新同一AUTO记录，修订号递增；无变化内容、时间、修订号均不变 |
| POST /{id}/restore-copy | 新建项目并正确重映射关联；原项目、发布、模拟和进度不变 |

恢复是“新项目副本”，不是原地覆盖；未提交文字回到表单等待确认。请求字段与大小限制见[功能说明](17-历史保存与自动草稿说明.md)。不要直接SQL篡改快照来代替正常业务验收。
