# 阶段任务计划（两名开发者）

## 1. 分工原则

- 开发者 A 主责后端、数据库、规则与图算法。
- 开发者 B 主责前端、交互、页面状态与演示素材。
- 领域模型、API、数据库变更、权限和验收脚本必须共同评审。
- 每个模块采用“后端契约先行、前端使用 mock 并行、联调收口”的方式。

## 2. 五周路线

| 阶段 | 开发者 A | 开发者 B | 共同任务 | 阶段验收 |
|---|---|---|---|---|
| 第 0 阶段：框架与立项（已完成） | Spring Boot 分层、JWT、项目 Service、MyBatis、schema | Vue/Vite、登录、项目页、API 封装、工作台 | 确认范围、Git 规则、接口格式 | 能注册、登录、创建和查看项目 |
| 第 1 周：需求与基础业务 | 成员邀请/角色校验；世界观、角色 CRUD；补单测 | 项目设置、成员页、世界观和角色页 | 用例、业务实体、ER 初稿、UI 原型 | 两个账户以不同权限协作；角色资料可维护 |
| 第 2 周：剧情图 | 节点/选择 API、引用校验、批量保存事务 | Vue Flow 画布、节点表单、连接与自动保存 | 节点数据契约和序列图 | 搭建不少于 10 节点、2 结局的剧情图 |
| 第 3 周：状态与模拟 | 变量/条件/效果、规则引擎、会话和快照 | 规则编辑器、玩家模拟器、状态变化面板 | 规则案例与异常边界评审 | 从起点走到结局，每步状态可回放 |
| 第 4 周：检测与质量 | BFS/DFS 检测、问题记录、集成测试 | 检测结果定位、反馈页、空态和错误态 | 端到端测试、修复 P0 缺陷 | 自动识别孤立、不可达、死路、循环 |
| 第 5 周：文档与答辩缓冲 | 部署脚本、性能/安全检查、后端说明 | UI 整理、演示数据、截图/视频 | 总报告、个人小结、大模型说明、答辩演练 | 新环境可部署；8 分钟内完成演示闭环 |

## 3. 每周固定节奏

| 时间 | 活动 | 产出 |
|---|---|---|
| 周一 | 本周范围确认与接口评审 | Issue、接口字段、完成定义 |
| 周二至周四 | 各自主责开发，必要时结对 | 小粒度提交和单元测试 |
| 周五 | 联调与异常流测试 | 可演示纵向切片 |
| 周末 | 文档补齐、回顾和下周拆分 | 周报、风险清单、截图 |

## 4. P0 任务清单

### 基础与权限

- [x] 注册、登录、BCrypt、JWT
- [x] 项目创建、列表、详情、编辑、归档
- [x] OWNER/EDITOR/TESTER 权限基础
- [ ] 邀请/移除成员、修改成员角色
- [ ] 管理员禁用用户的最小后台

### 设定与剧情

- [ ] 世界观条目 CRUD
- [ ] 角色档案、关系、知识 CRUD
- [ ] 节点 CRUD、起点唯一约束
- [ ] 选项创建、重连、排序与引用检查
- [ ] Vue Flow 图形编辑和坐标持久化

### 状态与测试

- [ ] 状态变量 CRUD 和类型校验
- [ ] 条件组与效果编辑
- [ ] 规则引擎单元测试不少于 20 个边界案例
- [ ] 创建会话、获取可用选择、执行选择
- [ ] 步骤与前后状态快照、重新开始

### 检测与交付

- [ ] 孤立、不可达、死路、循环检测
- [ ] 检测问题定位和处理状态
- [ ] 端到端演示数据
- [ ] 部署、测试和总报告

## 5. 阶段门禁

一个阶段只有同时满足以下条件才算完成：

1. 主流程和至少两个异常流可复现。
2. 所有写操作都验证当前用户和 `projectId`。
3. 后端测试通过，前端类型检查和构建通过。
4. 接口文档、数据库变更和截图同步更新。
5. 另一名成员能够按 README 在新环境运行。

## 6. 答辩演示脚本

1. 以 OWNER 登录并创建剧情项目。
2. 添加角色、秘密知识和两个状态变量。
3. 在图上创建主线、隐藏分支和两个结局。
4. 故意留下一个孤立节点，运行检测并定位。
5. 进入模拟器，展示条件导致的选项显隐和状态变化。
6. 到达隐藏结局，查看路径和每一步快照。
7. 简述 AI 增强层及其失败不影响核心功能的设计。
