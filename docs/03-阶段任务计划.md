# 阶段任务计划（三人团队）

## 1. 分工原则

- 开发者 A 主责 Java 后端、接口、权限、事务、规则与图算法，并配合数据库联调。
- 开发者 B 主责前端、数据库、交互和页面状态；数据库工作包括 E-R 设计、MySQL 建表 SQL、迁移脚本、演示数据及 Navicat 操作记录。
- 成员 C 主责需求与设计材料、测试验收、演示组织和答辩，兼顾演示数据、验收脚本及小范围缺陷修复。
- A、B 是主要开发者；C 的开发量相对较少，但必须完成可独立验收、可在 Git 记录中追踪的代码或测试任务。
- 领域模型、API、数据库变更、权限和验收脚本由对应负责人评审，关键范围与答辩口径由三人共同确认。
- 每个模块采用“后端契约先行、前端使用 mock 并行、联调收口”的方式。

## 2. 五周路线

| 阶段 | 开发者 A（后端主开发） | 开发者 B（前端与数据库主开发） | 成员 C（答辩与质量） | 共同任务 | 阶段验收 |
|---|---|---|---|---|---|
| 第 0 阶段：框架与立项（已完成） | Spring Boot 分层、JWT、项目 Service、MyBatis | Vue/Vite、登录、项目页、API 封装、工作台；数据库 schema 初稿 | 整理课程要求、功能清单和立项材料 | 确认范围、Git 规则、接口格式 | 能注册、登录、创建和查看项目 |
| 第 1 周：需求与基础业务 | **已完成：**成员邀请/角色校验；世界观、角色 CRUD；补单测 | 项目设置、成员页、世界观和角色页；完善 E-R 图、建表 SQL 和 Navicat 初始化验证 | 完善用例、业务实体和验收用例 | UI 原型、数据字段与接口评审 | 两个账户以不同权限协作；角色资料可维护 |
| 第 2 周：剧情图 | **已完成：**节点/选择 API、引用校验、批量保存事务 | Vue Flow 画布、节点表单、连接与自动保存；维护节点相关表和迁移 SQL | 绘制序列图；准备不少于 10 节点、2 结局的演示剧情数据 | 节点数据契约评审 | 剧情图可创建、连接、保存和重新加载 |
| 第 3 周：状态与模拟 | 变量/条件/效果、规则引擎、会话和快照 | 规则编辑器、玩家模拟器、状态变化面板；维护状态与会话表 SQL | 编写边界验收脚本，补充规则测试案例或修复小范围缺陷 | 规则案例与异常边界评审 | 从起点走到结局，每步状态可回放 |
| 第 4 周：检测与质量 | BFS/DFS 检测、问题记录、后端集成测试 | 检测结果定位、反馈页、空态和错误态；准备测试库与 SQL 数据 | 执行端到端测试、记录缺陷、复测并整理测试报告 | 集中修复 P0 缺陷 | 自动识别孤立、不可达、死路、循环 |
| 第 5 周：文档与答辩缓冲 | 后端部署说明、性能/安全检查 | UI 整理、数据库初始化说明、Navicat 截图、演示数据与 SQL 验证 | 汇总总报告和个人材料；制作答辩稿、演示脚本、常见问答并组织演练 | 交叉审阅、大模型使用说明、最终验收 | 新环境可部署；8 分钟内完成演示闭环 |

## 3. 每周固定节奏

| 时间 | 活动 | 产出 |
|---|---|---|
| 周一 | 本周范围确认与接口评审 | Issue、接口字段、完成定义 |
| 周二至周四 | A、B 主责开发；C 同步验收材料与少量开发任务 | 小粒度提交、单元测试和验收用例 |
| 周五 | 三人联调与异常流测试 | 可演示纵向切片、缺陷记录 |
| 周末 | C 汇总文档与演示口径，A、B 复核技术内容 | 周报、风险清单、截图和答辩问题库 |

## 5. 阶段门禁

一个阶段只有同时满足以下条件才算完成：

1. 主流程和至少两个异常流可复现。
2. 所有写操作都验证当前用户和 `projectId`。
3. 后端测试通过，前端类型检查和构建通过。
4. 接口文档、数据库变更和截图同步更新。
5. 至少一名非模块负责人能够按 README 在新环境运行。
6. 负责人、提交记录、测试记录和文档证据能够对应，三名成员均有可说明的个人贡献。

## 6. 答辩演示脚本

成员 C 主讲并控制整体节奏，A 负责回答后端、接口、算法与安全问题，B 负责回答前端、数据库、SQL、Navicat 操作和可视化问题。三人均需熟悉完整业务闭环，避免只了解各自局部。

1. 以 OWNER 登录并创建剧情项目。
2. 添加角色、秘密知识和两个状态变量。
3. 在图上创建主线、隐藏分支和两个结局。
4. 故意留下一个孤立节点，运行检测并定位。
5. 进入模拟器，展示条件导致的选项显隐和状态变化。
6. 到达隐藏结局，查看路径和每一步快照。
7. 简述 AI 增强层及其失败不影响核心功能的设计。
