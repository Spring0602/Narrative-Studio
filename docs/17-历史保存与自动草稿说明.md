# 历史保存与自动草稿

更新日期：2026-09-24。代码与 SQL 已准备；真实 MySQL 升级和浏览器实机验收仍待完成。无需 Docker。

## 保存规则

- 点击工作区顶部“保存版本”才创建手动历史。全项目共享最近 5 份，第 6 次成功保存后淘汰最早一份。普通节点、角色等表单保存不增加历史版本；即使内容相同，主动保存版本也计一次。
- 自动保存每 10 分钟检查一次：创作内容和未提交草稿均无变化则不写入、不更新时间；有变化覆盖本人唯一自动草稿，保留同一记录 ID 并递增修订号，不占手动 5 份。
- 首次进入以当前创作内容为基准；已存在恢复草稿时先暂停，用户检查后显式启用。网络失败或其他窗口更新时暂停并提示，不静默覆盖。
- 页面关闭后不在后台继续运行。浏览器后台可能延迟计时，回到页面时补一次到期检查，不连发多次。
- 未提交编辑即时保留本机草稿，用于不足 10 分钟就意外退出的恢复。关闭/取消表单会清除该表单草稿，离开模块保留；撤销回打开时内容不再算变更。本机存储容量、禁用存储、清理浏览器数据会影响恢复，界面会提示写入失败。
- 自动草稿不是无限历史；一次错误编辑仍可能在下一次检查覆盖自动草稿。重要修改前请主动保存版本。

## 保存范围与恢复

保存项目名称/说明、世界观、全部角色（含归档）、节点内容与布局、选项、变量及持久化范围、普通条件/效果、复杂解锁规则、角色关系/知识、节点出场角色、选项草稿。

未提交表单包括项目资料、节点、选项、世界观、角色、变量、角色关系/知识、出场角色、选项规则与选项草稿。每类编辑表单保留当前草稿；不是逐字修改历史。尚未导入的 Excel 文件、导入映射、账户设置、筛选和临时弹窗不属于项目快照。

恢复必须先预览、填写名称并确认，**生成可继续编辑的新项目副本**。原项目及其 5 份手动记录、自动草稿、成员、发布版本、模拟记录与跨局进度不变；这些运行数据不复制到新项目。新项目由恢复者拥有，其他成员需重新邀请。数据库节点/选项等 ID 重新分配，外键和草稿引用同步映射，节点业务编号保持不变。

快照中的未提交文字恢复到编辑表单，不直接当作正式内容写入。请逐个模块检查后保存。只读成员可以查看项目手动历史，不能保存或恢复；自动草稿仅本人可读。归档项目不可写。

## 接口

均需 JWT，项目路径前缀为 `/api/projects/{projectId}/saves`。

| 方法/路径 | 用途 |
| --- | --- |
| GET | 手动记录、本人自动草稿及当前内容摘要 |
| GET /{id} | 只读预览快照 |
| POST | 主动保存版本 |
| PUT /auto | 比较内容，按预期修订号更新自动草稿 |
| POST /{id}/restore-copy | 确认后恢复新项目 |

保存体：`{label,drafts,expectedRevision,baselineHash}`，手动保存 expectedRevision 为 0；自动初次修订号为 0，后续用响应修订号。baselineHash 为首次 GET 返回的 currentHash。恢复体：`{confirm:true,expectedRevision,name}`。冲突返回 409，重新预览后再操作，不能盲目重试覆盖。

所有写操作在项目锁和事务内完成。摘要使用有序 JSON，忽略更新时间等非创作字段。草稿上限 1MB、完整快照 8MB、单类记录 10000 条，超限显式拒绝，不截断保存。恢复失败整笔回滚，不留下半个项目。
