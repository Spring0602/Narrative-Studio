# 修改密码失败问题报告

## 问题标题

修改密码时输入错误的当前密码，页面跳回登录页，但密码实际没有修改。

## 测试环境

- 用户角色：TESTER
- 页面：账户设置
- 功能：修改密码
- 测试日期：2026-09-18

## 复现步骤

1. 登录 TESTER 账号。
2. 进入项目内的「账户设置」。
3. 在「修改密码」区域输入错误的当前密码。
4. 输入符合长度要求的新密码，并再次确认新密码。
5. 点击「修改密码」。
6. 重新使用原密码登录。

## 实际结果

- 点击修改后页面直接跳回登录页。
- 没有明确提示“当前密码错误”。
- 使用原密码仍然可以登录。
- 新密码没有生效。

## 预期结果

- 后端应拒绝错误当前密码，不修改密码。
- 页面应停留在账户设置页。
- 页面应明确提示“当前密码错误”。
- 不应因为修改失败而强制退出登录。

## 问题判断

密码没有被错误修改，账号安全性目前未发现问题。

但页面行为和错误提示存在问题：修改密码请求失败时，前端似乎统一清除了登录状态或跳转到了登录页，导致用户无法直接看到失败原因。

## 建议修复

1. 后端验证当前密码失败时返回明确的业务错误信息，例如 HTTP 400 或 401。
2. 前端捕获该错误并显示“当前密码错误”。
3. 只有密码修改成功后，才清除 JWT 并跳转到登录页。
4. 修改失败时保留当前页面及表单状态，避免误导用户。

## 验收标准

- 输入错误当前密码时，密码不会改变。
- 原密码仍可登录。
- 新密码不能登录。
- 页面不跳转到登录页。
- 用户能看到明确的错误提示。
- 输入正确当前密码和合规新密码后，修改成功并按设计重新登录。
